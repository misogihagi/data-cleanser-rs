
## 用語集のスクレイピング方式

用語集のコンテンツ構造に応じて、主に以下の4つのパターンがあります。

---

### 1. 階層型リンク構造（最も多いパターン）

最も一般的な方式で、複数のステップを踏んで詳細情報にたどり着きます。

1.  **インデックス**にアクセス（例: あ行、aから始まる、などのカテゴリ）。
2.  インデックスに含まれる**各カテゴリのリンク**をたどる。
3.  カテゴリページに含まれる**各用語の詳細ページへのリンク**をたどる。
4.  詳細ページから**用語のタイトルと説明**を取得。

#### 必要な情報

* インデックスの **URL**
* カテゴリへのリンクの **CSSセレクタ**
* 用語の詳細ページへのリンクの **CSSセレクタ**
* 用語のタイトルと説明の **CSSセレクタ**

---

### 2. カテゴリページ集約型（次に多いパターン）

インデックスからカテゴリに移動した後、そのページ内で複数の用語がまとめて取得できる方式です。

1.  **インデックス**にアクセス（例: あ行、aから始まる、などのカテゴリ）。
2.  インデックスに含まれる**各カテゴリのリンク**をたどる。
3.  カテゴリページ自体に**複数の用語とその説明**が一覧で掲載されている。
4.  一つの **CSSセレクタ** で複数の用語のタイトルと説明を一括取得。

#### 必要な情報

* インデックスの **URL**
* カテゴリへのリンクの **CSSセレクタ**
* 用語のタイトルと説明の **CSSセレクタ**（複数の用語に対応）

---

### 3. API利用型（あまりないパターン）

ウェブサイト側が**API（Application Programming Interface）**を用意している場合です。

* **独自に構築**されていることが多いため、個々のAPI仕様に合わせてスクレイピング（またはデータ取得）の仕組みを構築する必要があります。

---

### 4. 正規化されていないパターン

上記いずれの構造にも当てはまらず、**一貫性のない、または予測が困難な構造**をしている場合です。

* 特定のルールに基づいてコンテンツを取得することが難しく、個別の対応やより複雑な解析が必要になります。

```mermaid
    B --> D{カテゴリページ集約型<br> (次に多い)};
    B --> E{API提供型<br> (あまりない)};

    C --> C1[インデックスURLにアクセス];
    C1 --> C2[カテゴリリンクを取得];
    C2 --> C3[用語の詳細リンクを取得];
    C3 --> C4[詳細ページからタイトルと説明を取得];

    D --> D1[インデックスURLにアクセス];
    D1 --> D2[カテゴリリンクを取得];
    D2 --> D3[カテゴリページから複数の<br>用語と説明をまとめて取得];

    E --> E1[APIエンドポイントの特定];
    E1 --> E2[独自仕様に基づきデータ取得];

    F --> F1[個別の解析/対応が必要];
```

## 図の解説

| ノード | 説明 |
| :--- | :--- |
| **A** | スクリーピングの開始点。 |
| **B** | 用語集のウェブサイト構造を判断する分岐点。 |
| **C** | **階層型リンク構造**（最も多い）：インデックス $\to$ カテゴリ $\to$ 各用語詳細ページ、とリンクをたどる方式。 |
| **D** | **カテゴリページ集約型**（次に多い）：インデックス $\to$ カテゴリページ、で、カテゴリページ内に全用語がリストされている方式。 |
| **E** | **API提供型**（あまりない）：ウェブサイトがデータ取得用のAPIを用意している方式。 |
| **F** | **正規化されていないパターン**：構造が一貫しておらず、個別の対応が必要な方式。 |
| **C1〜C4** | 階層型リンク構造の具体的なステップ。 |
| **D1〜D3** | カテゴリページ集約型の具体的なステップ。 |
| **E1〜E2** | API提供型の具体的なステップ。 |
| **F1** | 正規化されていないパターンへの対応。 |
